1. CBC Encryption and Decryption Math

In Cipher Block Chaining (CBC) mode, each plaintext block $P_i$ is XORed with the previous ciphertext block $C_{i-1}$ before encryption:

Encryption: C_i = E_K(P_i XOR C_{i-1}) [with C_0 = IV]
Decryption: P_i = D_K(C_i) XOR C_{i-1}

Define the Intermediate State as $I_i = D_K(C_i)$. Note that $I_i$ is completely independent of $C_{i-1}$ and only depends on the secret key $K$ and $C_i$.

2. Vaudenay's Padding Oracle Discovery (2002)

Serge Vaudenay demonstrated that if a server reveals whether the PKCS#7 padding of decrypted ciphertext is valid or invalid, an adversary can determine $I_i$ byte-by-byte without the secret key.

To recover byte $k$ (counting from 15 down to 0), we set target padding byte $pad = 16 - k$. We craft a candidate block $C'_{i-1}$:

For known bytes j > k: C'_{i-1}[j] = I_i[j] XOR pad
For target byte k: C'_{i-1}[k] = candidate in [0, 255]
When Oracle returns "Valid Padding":
    I_i[k] XOR candidate = pad ===> I_i[k] = candidate XOR pad
    Original Plaintext: P_i[k] = I_i[k] XOR C_{i-1}[k]

3. Algorithmic Complexity Comparison

Brute-Force Key Search:

Complexity: $\mathcal{O}(2^{128})$ operations.
Time required: Billions of years even with supercomputers.

Padding Oracle Attack:

Complexity: $\mathcal{O}(256 \times L)$ oracle queries for $L$ bytes.
For a 16-byte block: $\approx 128 \times 16 = 2048$ queries (fraction of a second!).

4. Viva Preparation: Questions Professor May Ask & Winning Answers

Q1: Why does changing the error message to a generic "Decryption Failed" not fully fix the vulnerability?

Ans: Even if error messages are identical, side-channel timing differences (e.g., the Lucky Thirteen attack, CVE-2013-0169) leak whether the padding validation took fewer CPU cycles than MAC verification. Furthermore, uniform errors do not prevent bit-flipping malleability.

Q2: Why is AES-GCM (Authenticated Encryption) completely immune to padding oracle attacks?

Ans: AES-GCM operates in Counter (CTR) mode combined with Galois MAC (GMAC). Counter mode does not require padding at all. In addition, the 128-bit authentication tag is checked first. Any modification to ciphertext causes immediate rejection before decryption.

Q3: Mention historical real-world attacks based on this vulnerability.

Ans: POODLE (CVE-2014-3566) against SSL 3.0 / TLS; Lucky Thirteen (CVE-2013-0169); ASP.NET padding oracle (MS10-070); XML Encryption padding oracle (CVE-2011-1096).
